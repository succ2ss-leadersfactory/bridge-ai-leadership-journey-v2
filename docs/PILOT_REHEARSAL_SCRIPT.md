# Bridge AI Leadership Journey v2.0 파일럿 리허설 시나리오

이 문서는 교육 전 강사가 10~15분 안에 웹앱 전체 흐름을 점검하기 위한 리허설 스크립트입니다.

## 1. 리허설 목표

리허설의 목표는 기능을 완벽히 검수하는 것이 아니라, 교육장 운영 중 막힐 가능성이 높은 지점을 빠르게 확인하는 것입니다.

확인할 핵심 흐름은 다음입니다.

```text
교육생 입장
→ 세션 Map
→ 세션별 라운드 Map
→ 판단/입력 진행
→ AI 프롬프트 수정 및 복사
→ AI 답변 골라보기
→ 2주 실행안 3개 작성
→ 후배에게 할 말 3~5줄 작성
→ 저장
→ Google Sheets 반영
→ 강사용 대시보드 조회
```

## 2. 리허설 준비물

- 강사용 PC 1대
- 테스트용 스마트폰 1대
- Vercel 배포 URL
- 강사용 대시보드 URL
- Google Sheets 원본
- Apps Script Web App URL

## 3. 리허설 역할

| 역할 | 수행 내용 |
|---|---|
| 강사 | 강사용 대시보드와 Google Sheets 확인 |
| 테스트 교육생 | 스마트폰으로 교육생 화면 진행 |
| 운영 보조자 | 저장 여부, 화면 오류, 네트워크 상태 확인 |

1명이 모두 수행해도 됩니다.

## 4. 10~15분 리허설 절차

### 0:00~1:00 접속 확인

강사용 PC에서 다음을 엽니다.

```text
https://<vercel-domain>/?view=instructor
```

스마트폰에서 다음을 엽니다.

```text
https://<vercel-domain>/
```

확인합니다.

- [ ] 스마트폰에서 교육생 화면이 열린다.
- [ ] PC에서 강사용 대시보드가 열린다.
- [ ] 대시보드에서 데이터 새로고침 버튼이 보인다.

### 1:00~3:00 교육생 입장 및 세션 선택 테스트

스마트폰에서 입력합니다.

```text
팀명: 테스트팀
닉네임: 테스트과장
```

세션은 Session 1을 선택합니다.

확인합니다.

- [ ] 팀명/닉네임 입력 전에는 다음 버튼이 비활성화된다.
- [ ] 입력 후 세션 Map으로 이동한다.
- [ ] Session 1, Session 2, Session 3이 보인다.
- [ ] Session 1을 선택하면 선택 표시가 보인다.
- [ ] Session 1 선택 후 라운드 Map으로 이동한다.

### 3:00~4:00 세션별 라운드 Map 확인

Session 1 라운드 Map에서 R2를 선택합니다.

확인합니다.

- [ ] Session 1에는 R1, R2만 보인다.
- [ ] R2의 후배가 이서연 대리로 표시된다.
- [ ] R2를 선택하면 선택 표시가 보인다.
- [ ] 선택한 장면 시작 버튼으로 R2가 시작된다.

### 4:00~7:00 중간 단계 빠른 진행

각 입력 단계에는 짧게 입력합니다.

```text
후배 행동 읽기: 빠르게 진행하지만 마지막 확인이 부족해 보입니다.
선택 이유: 속도는 살리고 제출 전 확인 루틴을 붙이는 것이 필요하다고 봤습니다.
딜레마: 바로 지적하면 빨리 고칠 수 있지만, 후배의 실행 강점까지 위축될 수 있습니다.
AI 답변 참고: 제출 전 체크 루틴 제안은 참고하겠습니다.
AI 답변 수정: 표현은 우리 조직 말투에 맞게 고치겠습니다.
AI 답변 주의: 성격을 단정하는 표현은 쓰지 않겠습니다.
```

확인합니다.

- [ ] 필수 입력 전에는 다음 버튼이 비활성화된다.
- [ ] 입력 후 다음 단계로 이동된다.
- [ ] 상단에 임시 저장 표시가 나온다.

### 7:00~9:00 AI 프롬프트 복사 테스트

AI 프롬프트 화면에서 다음을 확인합니다.

- [ ] 프롬프트가 자동 생성된다.
- [ ] 프롬프트 안에 R2 상황과 선택 이유가 반영된다.
- [ ] 프롬프트 안에 이서연 대리로 표시된다.
- [ ] 텍스트를 수정할 수 있다.
- [ ] 프롬프트 복사 버튼이 작동한다.
- [ ] 복사 성공 메시지가 나온다.
- [ ] 외부 AI에 붙여넣을 수 있다.

### 9:00~11:00 최종 실행안 작성

2주 실행안은 3개만 입력합니다.

```text
2주 뒤 보고 싶은 작은 변화: 제출 전 기준 3가지를 스스로 확인한다.
이번 주 맡겨볼 작은 행동: 보고서 초안을 제출하기 전 숫자, 문구, 공유 대상을 체크한다.
과장이 도와줄 방식: 첫 2회는 체크 기준을 함께 보고, 이후에는 이서연 대리가 먼저 점검표를 가져오게 한다.
```

후배에게 할 말은 하나의 편집창에 3~5줄로 입력합니다.

```text
이서연 대리, 빠르게 움직이는 점은 분명한 강점입니다.
다만 제출 전 마지막 확인이 빠지면 좋은 속도가 오히려 부담이 될 수 있어요.
이번 주에는 제출 전에 숫자, 문구, 공유 대상 세 가지만 먼저 확인해 봅시다.
처음 두 번은 제가 같이 봐드릴게요.
```

확인합니다.

- [ ] 2주 실행안은 3개 입력칸만 보인다.
- [ ] 세 항목 입력 후 다음으로 이동된다.
- [ ] 후배에게 할 말 화면은 하나의 편집창으로 보인다.
- [ ] 3줄 이상 입력 후 결과 화면으로 이동된다.
- [ ] 결과 화면에 3개 실행안과 후배에게 할 말이 표시된다.

### 11:00~13:00 저장 테스트

결과 화면에서 `작성한 내용 저장하기`를 누릅니다.

확인합니다.

- [ ] 저장 전에는 라운드 Map으로 돌아가기 버튼이 비활성화된다.
- [ ] 저장 중 메시지가 보인다.
- [ ] 저장 성공 메시지가 보인다.
- [ ] 저장 성공 후 라운드 Map으로 돌아가기 버튼이 활성화된다.
- [ ] Google Sheets `Participants` 시트에 테스트팀 행이 생긴다.
- [ ] Google Sheets `Responses` 시트에 R2 응답 행이 생긴다.

### 13:00~15:00 라운드 완료 및 대시보드 테스트

라운드 Map으로 돌아간 뒤 강사용 대시보드에서 `데이터 새로고침`을 누릅니다.

확인합니다.

- [ ] R2 카드에 완료 뱃지가 보인다.
- [ ] 참여자 수가 증가한다.
- [ ] 전체 응답 수가 증가한다.
- [ ] 팀별 진행 현황에 테스트팀이 보인다.
- [ ] 최근 저장 응답에 테스트과장이 보인다.
- [ ] 응답을 펼치면 2주 실행안과 후배에게 할 말이 보인다.

## 5. 리허설 통과 기준

아래 6개가 통과되면 파일럿 진행이 가능합니다.

- [ ] 스마트폰 교육생 화면 접속 가능
- [ ] 세션 Map과 세션별 라운드 Map 정상 작동
- [ ] AI 프롬프트 복사 가능
- [ ] 작성한 내용 저장하기 작동
- [ ] Google Sheets에 저장됨
- [ ] 강사용 대시보드에서 조회됨

## 6. 리허설 실패 시 판단 기준

### 저장만 실패한 경우

교육 진행은 가능하지만, 교육생에게 최종 결과를 별도 캡처하게 해야 합니다. Apps Script와 Vercel 환경변수를 우선 확인합니다.

### 대시보드만 실패한 경우

교육 진행은 가능합니다. Google Sheets 원본으로 운영 모니터링을 대체합니다.

### 교육생 화면 이동이 실패한 경우

파일럿 전에 반드시 수정해야 합니다.

### AI 프롬프트 복사가 실패한 경우

텍스트 박스를 길게 눌러 직접 복사하는 방식으로 대체 안내할 수 있습니다.

## 7. 교육생에게 안내할 한 문장

```text
오늘 웹앱은 정답을 맞히는 게임이 아니라, 여러분이 후배를 어떻게 읽고 어떤 육성 판단을 하는지 남겨보는 실습 도구입니다.
```

## 8. 강사용 대시보드 안내 멘트

```text
여러분이 저장한 내용은 강사용 화면에서 팀별·라운드별로 모아 보겠습니다. 개인 평가용이 아니라 토의와 학습을 위한 자료입니다.
```
