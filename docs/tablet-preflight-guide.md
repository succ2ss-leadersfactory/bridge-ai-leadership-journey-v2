# 태블릿 기준 Preflight 운영 점검 가이드

이 문서는 강사 또는 운영자가 교육장 도착 후 태블릿으로 `Bridge AI Leadership Journey v2.0`의 저장 연동 상태를 빠르게 점검하기 위한 안내서입니다.

## 1. 점검 목표

교육 시작 전 아래 4가지를 확인합니다.

1. 교육생 화면이 열린다.
2. 강사용 대시보드가 열린다.
3. Google Sheets 시트와 헤더가 최신 v2 구조로 준비되어 있다.
4. 저장된 데이터가 강사용 대시보드에서 조회된다.

## 2. 접속 주소

Vercel 배포 주소 뒤에 아래 경로를 붙입니다.

| 목적 | 경로 |
|---|---|
| 교육생 화면 | `/` |
| 강사용 대시보드 | `/?view=instructor` |
| 운영 전 점검 화면 | `/?view=check` |

## 3. 태블릿에서 먼저 열 화면

운영자는 먼저 아래 화면을 엽니다.

```text
https://Vercel-배포주소/?view=check
```

화면 제목은 다음과 같이 보여야 합니다.

```text
운영 전 연결 점검
```

## 4. 1단계: 환경변수 확인

화면의 `Vercel 환경변수` 카드가 다음처럼 표시되는지 확인합니다.

```text
정상
Google Apps Script URL 환경변수가 설정되어 있습니다.
```

### 확인 필요로 표시될 때

Vercel 프로젝트의 Environment Variables에서 아래 값이 빠졌을 가능성이 큽니다.

```text
VITE_GOOGLE_SCRIPT_WEBAPP_URL
```

조치:

1. Vercel 프로젝트 Settings로 이동합니다.
2. Environment Variables에서 위 변수를 등록합니다.
3. 값을 Apps Script Web App `/exec` URL로 입력합니다.
4. Vercel을 다시 배포합니다.

## 5. 2단계: 시트/헤더 점검

`시트/헤더 점검` 버튼을 누릅니다.

정상이라면 다음이 표시됩니다.

```text
시트와 헤더 점검이 완료되었습니다. 확인된 시트 2개
```

그리고 아래 요약 영역에 다음 2개 시트가 표시되어야 합니다.

- `Participants`
- `Responses`

### 확인할 핵심 컬럼

`Responses`는 다음 컬럼을 포함해야 합니다.

```text
growth_goal
two_week_task
leader_support
check_timing
watch_out
final_line_1
final_line_2
final_line_3
final_line_4
final_line_5
```

### 실패할 때 우선 확인

| 증상 | 확인할 것 |
|---|---|
| 시트/헤더 점검 실패 | Apps Script에 최신 `apps-script/Code.gs`가 반영되었는지 확인 |
| Active spreadsheet 오류 | Apps Script가 Google Sheets에서 열린 바운드 스크립트인지 확인 |
| 권한 오류 | Apps Script 배포 권한이 외부 호출 가능 상태인지 확인 |
| `/dev` URL 사용 | 운영 URL이 `/exec`로 끝나는지 확인 |

## 6. 3단계: 조회 테스트

`조회 테스트` 버튼을 누릅니다.

정상이라면 다음 메시지가 표시됩니다.

```text
대시보드 데이터를 불러왔습니다.
```

그리고 현재 조회된 데이터 영역에 다음이 표시됩니다.

```text
참여자 0명 이상
응답 0건 이상
```

파일럿 전에는 0이어도 정상입니다. 테스트 저장 후 숫자가 증가하면 됩니다.

## 7. 4단계: 화면 링크 확인

Preflight 화면에서 아래 두 링크를 눌러봅니다.

1. `교육생 화면 열기`
2. `강사용 대시보드 열기`

확인할 것:

- 교육생 화면에서 팀명/닉네임 입력 화면이 보인다.
- 강사용 대시보드에서 `Bridge AI Leadership Journey 운영 대시보드`가 보인다.

## 8. 5단계: 테스트 저장 확인

교육생 화면에서 테스트 라운드 하나를 끝까지 진행합니다.

권장 테스트:

```text
Session 1 → R2
```

테스트 입력은 `docs/manual-test-script.md`의 샘플을 사용합니다.

저장 후 확인:

1. 결과 화면에서 `최종본 저장하기`를 누릅니다.
2. 저장 완료 메시지를 확인합니다.
3. Preflight 화면으로 돌아옵니다.
4. `조회 테스트`를 다시 누릅니다.
5. 참여자 수와 응답 수가 증가했는지 확인합니다.
6. 강사용 대시보드에서 `데이터 새로고침`을 누릅니다.
7. 최근 저장 응답에 테스트 팀이 보이는지 확인합니다.

## 9. 교육 시작 전 최종 판정

아래 5개가 모두 통과되면 교육 운영 가능 상태로 봅니다.

- [ ] Vercel 환경변수 카드가 정상이다.
- [ ] 시트/헤더 점검이 성공한다.
- [ ] Participants, Responses 시트가 확인된다.
- [ ] 조회 테스트가 성공한다.
- [ ] 테스트 저장 후 대시보드에서 응답이 보인다.

## 10. 현장 대체 운영 기준

저장 연동이 불안정할 경우에도 교육을 멈추지 않도록 아래 기준을 사용합니다.

| 상황 | 대체 운영 |
|---|---|
| 교육생 화면은 열리지만 저장이 안 됨 | 최종 화면을 캡처하게 하고, 팀별 대표 1명이 구두 공유 |
| AI 답변 자동분리가 안 됨 | AI 답변에서 필요한 문장을 복사해 직접 입력 |
| 강사용 대시보드 조회가 안 됨 | Google Sheets를 직접 열어 Responses 시트를 확인 |
| 일부 교육생 접속 실패 | 같은 팀 다른 기기에서 대표 입력 |
| 전체 네트워크 불안정 | 강사가 화면 시연 후 종이/메모 앱으로 대체 실습 |

## 11. 운영자 한 줄 체크

교육 시작 직전 운영자는 아래 한 줄만 확인합니다.

```text
Preflight 정상 → 테스트 저장 성공 → 대시보드 표시 확인
```
