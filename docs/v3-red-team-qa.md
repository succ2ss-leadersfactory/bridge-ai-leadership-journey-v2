# v3 Red Team QA · 교육생 현실성·전이성 검토

## 검토 기준

1. 과장급이 실제로 할 수 있는 행동인가
2. 선택지에서 정답이 너무 쉽게 보이지 않는가
3. 후배를 성격·세대로 단정하게 만들지 않는가
4. 새 정보가 첫 판단을 실제로 흔들 만큼 의미가 있는가
5. Case A~F가 서로 다른 브릿지 리더 역할을 연습하게 하는가
6. 모바일에서 읽고 선택하고 토의하기에 과밀하지 않은가
7. 이론이 선택 전에 정답을 유도하지 않고, 경험 뒤의 설명 렌즈로 작동하는가
8. AI가 리더 판단을 대체하지 않고 두 번째 의견으로 작동하는가
9. 실습 결과물이 현업에서 다시 사용할 수 있는가
10. 마지막 Playbook이 교육내용 요약이 아니라 자기 선택을 바탕으로 만들어지는가

## P0 발견 및 반영

### 1. 신호 선택에 명백한 오답이 포함됨

초기 v3에는 “젊은 세대는 원래 개인주의적”, “빠르게 일하는 사람은 원래 디테일이 약하다”처럼 교육생이 즉시 제외할 수 있는 보기가 있었다. 이 경우 관찰 훈련이 아니라 정답 찾기 문제가 된다.

**반영:** A~F 모두 5개 보기를 실제로 고려할 가치가 있는 경쟁 신호로 교체. 화면 문구도 “다섯 가지 모두 볼 가치가 있지만 지금 첫 대응에 중요한 2개를 고른다”로 수정.

### 2. 첫 선택 전에 장점·비용이 노출됨

선택 카드에서 좋은 점과 부담되는 점을 먼저 보여주면 교육생은 실제 행동보다 교육적으로 균형 잡힌 선택을 고르게 된다.

**반영:** 첫 선택 화면에서는 행동과 현실적 이유만 노출. 선택 이후 결과 화면에서만 `이 선택의 힘 / 놓칠 수 있는 비용`을 공개.

### 3. 이어하기가 실제 이어하기가 아니었음

Case Map에는 “이어하기”라고 표시되지만 기존 구현은 다시 상황 첫 화면으로 들어갔다.

**반영:** 각 Case별 `lastStep`을 localStorage에 저장하고 정확한 단계에서 복원. 완료 Case는 결과 화면으로 바로 재진입.

## P1 발견 및 반영

### 4. 마지막 Playbook이 자기 선택과 연결되지 않음

MORE/LESS 항목을 바로 고르면 교육과정이 권하는 행동을 고를 가능성이 높다.

**반영:** Playbook 시작 전에 A~F의 `처음 선택 / 새 정보 후 재결정`을 한 화면에 보여주고 자기 패턴을 본 후 MORE · LESS · NEXT 2 WEEKS를 정하도록 변경.

### 5. 레거시 v2 CSS가 v3에도 함께 번들됨

실행에는 필요하지 않은 과거 UI CSS가 v3 단일 HTML에 포함되어 파일 크기와 충돌 가능성을 늘렸다.

**반영:** v3 실행 진입점에서는 v3 CSS만 사용하도록 정리.

## 현재 유지하는 설계 원칙

- 6개 Case는 동일한 정답 패턴이 아니라 서로 다른 리더 역할을 연습한다.
- 자유입력은 Case당 핵심 산출물 2개 중심으로 제한한다.
- 팀 토의 메모는 선택 입력으로 유지한다.
- A/C는 AI 없이 인간 판단으로 끝까지 진행한다.
- B/D/E/F의 AI는 내 초안 작성 후에만 사용한다.
- 이론은 재결정 이후에만 노출한다.
- Case F는 세대·개인주의 프레임이 아니라 역할 경계, 공정성, 공동책임의 문제로 다룬다.

## 다음 파일럿 QA에서 볼 것

- 실제 과장급 3~5명이 Case A/F를 읽었을 때 “우리 조직에서도 있을 법하다”는 반응이 나오는가
- 첫 선택 A/B/C의 분포가 한 선택으로 과도하게 쏠리지 않는가
- 신호 5개 중 선택이 다양하게 갈리는가
- Case 하나를 휴대폰으로 완료하는 데 과도한 시간이 걸리지 않는가
- 팀 토의 질문이 설명 반복이 아니라 실제 의견 차이를 만들어내는가
- 이론 카드의 문장 길이가 모바일에서 부담되지 않는가
- AI 외부 전환이 수업 흐름을 끊는 정도가 어느 수준인가
