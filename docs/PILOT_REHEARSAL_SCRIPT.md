# Bridge AI Leadership Journey v2.0 파일럿 리허설 시나리오

이 문서는 교육 전 강사가 10~15분 안에 웹앱 전체 흐름을 점검하기 위한 리허설 스크립트입니다.

## 1. 리허설 목표

리허설의 목표는 기능을 완벽히 검수하는 것이 아니라, 교육장 운영 중 막힐 가능성이 높은 지점을 빠르게 확인하는 것입니다.

확인할 핵심 흐름은 다음입니다.

```text
교육생 입장
→ 라운드 선택
→ 판단/입력 진행
→ AI 프롬프트 복사
→ 2주 미니 육성 플랜 작성
→ 결과 저장
→ Google Sheets 반영
→ 강사용 대시보드 조회
```

## 2. 리허설 준비물

- 강사용 PC 1대
- 테스트용 스마트폰 1대
- Vercel 배포 URL
- 강사용 대시보드 URL
- Google Sheets 원본
- Apps Script Web App URL

## 3. 리허설 역할

| 역할 | 수행 내용 |
|---|---|
| 강사 | 강사용 대시보드와 Google Sheets 확인 |
| 테스트 교육생 | 스마트폰으로 교육생 화면 진행 |
| 운영 보조자 | 저장 여부, 화면 오류, 네트워크 상태 확인 |

1명이 모두 수행해도 됩니다.

## 4. 10분 리허설 절차

### 0:00~1:00 접속 확인

강사용 PC에서 다음을 엽니다.

```text
https://<vercel-domain>/?view=instructor
```

스마트폰에서 다음을 엽니다.

```text
https://<vercel-domain>/
```

확인합니다.

- [ ] 스마트폰에서 교육생 화면이 열린다.
- [ ] PC에서 강사용 대시보드가 열린다.
- [ ] 대시보드에서 데이터 새로고침 버튼이 보인다.

### 1:00~3:00 교육생 입장 테스트

스마트폰에서 입력합니다.

```text
팀명: 테스트팀
닉네임: 테스트과장
```

라운드는 R1을 선택합니다.

확인합니다.

- [ ] 팀명/닉네임 입력 전에는 시작 버튼이 비활성화된다.
- [ ] 입력 후 시작 버튼이 활성화된다.
- [ ] 라운드 선택 표시가 보인다.

### 3:00~6:00 중간 단계 빠른 진행

각 입력 단계에는 짧게 입력합니다.

```text
후배 행동 읽기: 기준이 없을 때 확인 욕구가 커지는 모습입니다.
선택 이유: 바로 답보다 기준을 남기는 것이 필요하다고 봤습니다.
딜레마: 속도와 후배의 판단 기준 형성 사이의 균형입니다.
AI 답변 참고: 기준 노트 제안은 참고하겠습니다.
AI 답변 수정: 표현은 우리 조직 말투에 맞게 고치겠습니다.
AI 답변 주의: 후배를 의존적이라고 표현한 부분은 쓰지 않겠습니다.
```

확인합니다.

- [ ] 필수 입력 전에는 다음 버튼이 비활성화된다.
- [ ] 입력 후 다음 단계로 이동된다.
- [ ] 상단에 임시 저장 표시가 나온다.

### 6:00~8:00 AI 프롬프트 복사 테스트

AI 프롬프트 화면에서 다음을 확인합니다.

- [ ] 프롬프트가 자동 생성된다.
- [ ] 텍스트를 수정할 수 있다.
- [ ] `프롬프트 복사하기` 버튼이 작동한다.
- [ ] 복사 성공 메시지가 나온다.
- [ ] 외부 AI에 붙여넣을 수 있다.

### 8:00~10:00 최종 결과 작성

2주 미니 육성 플랜은 짧게 입력합니다.

```text
성장 목표: 질문 전에 판단 기준 2가지를 먼저 말한다.
작은 과제: 고객 안내 문구를 기준-판단-확인 필요 여부로 정리한다.
과장의 지원: 첫 2회는 기준 표현을 함께 다듬는다.
점검 시점: 화요일과 목요일 오후 10분 점검한다.
주의할 점: 왜 또 묻느냐는 표현을 쓰지 않는다.
```

5줄 실행문은 다음처럼 입력합니다.

```text
1. 김민재 사원, 꼼꼼하게 확인하려는 태도는 좋습니다.
2. 다만 앞으로는 질문 전에 본인 기준을 먼저 말해봅시다.
3. 이번 주에는 고객 안내 문구를 기준 세 가지로 정리해 오세요.
4. 제가 처음 두 번은 기준 표현을 같이 봐드리겠습니다.
5. 목표는 질문을 줄이는 것이 아니라 판단 기준을 키우는 것입니다.
```

확인합니다.

- [ ] 모든 항목 입력 후 결과 화면으로 이동된다.
- [ ] 결과 요약이 보인다.

### 10:00~12:00 저장 테스트

결과 화면에서 `결과 저장하기`를 누릅니다.

확인합니다.

- [ ] 저장 중 메시지가 보인다.
- [ ] 저장 요청 성공 메시지가 보인다.
- [ ] Google Sheets `Participants` 시트에 테스트팀 행이 생긴다.
- [ ] Google Sheets `Responses` 시트에 R1 응답 행이 생긴다.

### 12:00~15:00 대시보드 테스트

강사용 대시보드에서 `데이터 새로고침`을 누릅니다.

확인합니다.

- [ ] 참여자 수가 증가한다.
- [ ] 전체 응답 수가 증가한다.
- [ ] 팀별 진행 현황에 테스트팀이 보인다.
- [ ] 최근 저장 응답에 테스트과장이 보인다.
- [ ] 응답을 펼치면 2주 미니 육성 플랜과 5줄 실행문이 보인다.

## 5. 리허설 통과 기준

아래 5개가 통과되면 파일럿 진행이 가능합니다.

- [ ] 스마트폰 교육생 화면 접속 가능
- [ ] AI 프롬프트 복사 가능
- [ ] 결과 저장 버튼 작동
- [ ] Google Sheets에 저장됨
- [ ] 강사용 대시보드에서 조회됨

## 6. 리허설 실패 시 판단 기준

### 저장만 실패한 경우

교육 진행은 가능하지만, 교육생에게 최종 결과를 별도 캡처하게 해야 합니다. Apps Script와 Vercel 환경변수를 우선 확인합니다.

### 대시보드만 실패한 경우

교육 진행은 가능합니다. Google Sheets 원본으로 운영 모니터링을 대체합니다.

### 교육생 화면 이동이 실패한 경우

파일럿 전에 반드시 수정해야 합니다.

### AI 프롬프트 복사가 실패한 경우

텍스트 박스를 길게 눌러 직접 복사하는 방식으로 대체 안내할 수 있습니다.

## 7. 교육생에게 안내할 한 문장

```text
오늘 웹앱은 정답을 맞히는 게임이 아니라, 여러분이 후배를 어떻게 읽고 어떤 육성 판단을 하는지 남겨보는 실습 도구입니다.
```

## 8. 강사용 대시보드 안내 멘트

```text
여러분이 저장한 내용은 강사용 화면에서 팀별·라운드별로 모아 보겠습니다. 개인 평가용이 아니라 토의와 학습을 위한 자료입니다.
```
