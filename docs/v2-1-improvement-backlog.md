# Bridge AI Leadership Journey v2.1 개선 백로그

이 문서는 v2.0 파일럿 운영 후 수집된 피드백을 v2.1 개선 과제로 정리하기 위한 백로그입니다.

## 1. 백로그 운영 원칙

파일럿 피드백은 아래 세 가지로 나누어 관리합니다.

| 분류 | 의미 | GitHub Issue 템플릿 |
|---|---|---|
| 기능 오류 | 저장, 화면, 버튼, 배포, 대시보드 오류 | 기능 오류 리포트 |
| 콘텐츠 수정 | 라운드 문구, 선택지, AI 프롬프트, 줄바꿈, 강사 멘트 수정 | 콘텐츠 수정 요청 |
| 운영 개선 | 교육장 진행, Preflight, 대시보드 활용, 장애 대응 개선 | 운영 개선 요청 |

## 2. 우선순위 기준

| 우선순위 | 기준 | 처리 시점 |
|---|---|---|
| P0 | 교육 진행이 막히는 오류 | 즉시 수정 |
| P1 | 파일럿 운영 품질에 큰 영향을 주는 문제 | 다음 파일럿 전 수정 |
| P2 | 교육 효과나 사용성을 높이는 개선 | v2.1 반영 |
| P3 | 장기 확장 또는 선택 기능 | v2.2 이후 검토 |

## 6. 파일럿 후 정리 절차

파일럿 종료 후 아래 순서로 정리합니다.

1. `docs/pilot-test-log-template.md`에 실제 테스트 결과를 기록합니다.
2. 발견된 문제를 GitHub Issue로 등록합니다.
3. Issue를 기능 오류, 콘텐츠 수정, 운영 개선으로 분류합니다.
4. P0/P1 이슈를 먼저 검토합니다.
5. v2.1 반영 범위를 확정합니다.
6. 수정 후 Vercel 배포 success를 확인합니다.
7. `docs/release-notes-v2-final.md`를 v2.1 릴리즈 노트로 복제·갱신합니다.

## 7. 파일럿에서 반드시 확인할 콘텐츠 항목

| 라운드 | 검증 포인트 |
|---|---|
| R2 | 대표 테스트 라운드로 문구가 자연스럽고 과하지 않은지 |
| R3 | 첫 안내 문장, 넘길 기준, 작은 재진입 역할이 현장감 있게 이해되는지 |
| R4 | 출처, 확정 여부, 표현 수위 검증 기준이 공항 안내 업무와 맞는지 |
| R5 | 유관 부서 일정 조율과 위임 경계가 실제 과장급 고민으로 느껴지는지 |
| BOSS | 보고 직전 압박과 작은 수습 역할이 과도하지 않고 교육적으로 작동하는지 |
